# A-09 · 미탐색 밴드 kNN화 + 추천 다양성 MMR (F-REC)

- 날짜 / 일정ID / 담당: 2026-06-20 · 4.x 추천 다듬기 · 김호준
- 브랜치 / 커밋: `feat/REC-03-mmr-band` · (커밋 예정)
- 한 줄 요약: A-08이 남긴 한계 **"미탐색 밴드가 아직 무게중심 거리 기준"**을 안전과 같은 **kNN 거리로 통일** + 안전·미탐색에 **MMR 다양성** 도입. λ·풀·밴드는 장르 데모 8종 스윕으로 결정.

## 만진 파일
- `backend/taste/services/areas.py` — 미탐색 밴드 도달성을 무게중심 거리 → **kNN 거리**(안전과 통일, knn 배열 재사용). 안전·미탐색 후보 dict에 `coord` 추가(MMR 다양성 계산용, 응답엔 노출 안 됨). 무게중심 `dist` 제거(`user_coord`는 지도·친구용으로만 유지).
- `backend/taste/services/recommend.py` — `mmr_select`(정규화 그리디 MMR) + 트랙별 λ + 풀40. `get_recommendations`가 풀(40) → MMR(10) → 메타 보강.
- `backend/taste/management/commands/show_areas.py` — 최종 MMR 결과를 보도록 `get_recommendations` 경유.

## 왜 / 어떻게
- **밴드 kNN화**: A-08에서 안전은 kNN화했으나 미탐색 "도달가능 밴드"는 무게중심 거리를 유지 → 다봉 취향의 골짜기 문제가 미탐색에도 남음. 안전에서 쓰는 `knn`(최근접 K=3 평균거리) 배열을 **그대로 재사용**해 밴드도 kNN 분위수로. 부수효과: kNN 거리 낮음 ≈ KDE 밀도 높음이라 **밴드의 핵심은 상한(허공 차단)**, 하한은 밀도가 어차피 거름.
- **MMR**: kNN/KDE가 가장 짙은 봉우리 하나에 뭉치는 걸 펼친다. 점수 = `λ·적합도 − (1−λ)·근접도`, 그리디. **정규화 필수**(적합도 변동폭은 좁고 근접도는 넓어 raw면 λ 무의미 → 풀 내 [0,1]로). 다양성 거리 = UMAP 좌표거리. 안전·미탐 둘 다 적용, 교차 dedup 없음(거리대 분리로 실측 교집합 ∅).

## 값 결정 (장르 데모 8종 평균, 봉우리 구분거리 1.0)
| 파라미터 | 채택 | 근거(스윕) |
|---|---|---|
| **안전 λ** | **0.7** | λ0.3은 장르일치 0.98로 샘, ≥0.5는 1.0. 신선함은 미탐 담당 → 적합 우선 + 같은 봉우리 중복만 제거 |
| **미탐 λ** | **0.5** | 봉우리 3.62·타장르 0.82(발견성). 0.3은 미미하게 더 펼침 |
| **풀** | **40** | 풀↑ → 풀 봉우리 1.4→2.5 늘지만 **추천 봉우리는 1.25 불변**(λ0.5가 추가 재료 안 씀) → 40 충분 |
| **밴드** | **(30,70)** | 무난. (20,80)이 약간 더 저밀도(7.2e-5 vs 9.5e-5) |

## 검증
- `manage.py check` 0 issues. 장르 데모 safe/unexp 각 10편. (페어 온보딩 머지 후 `accounts.0002_user_onboarded` 적용 필요했음 — 우리 코드 무관.)
- **MMR 전후**(음악): 안전이 `인사이드 르윈·라비앙로즈…`(음악 드라마 한 군집)에서 → `…스텝 업·앨빈과 슈퍼밴드…`(댄스/패밀리 음악 2번째 군집)를 끌어와 **다양화**. 공포는 한 군집이라 거의 불변(스윕 예측대로).
- **미탐색(kNN 밴드)**: 공포 → 다큐·음악다큐(서칭포슈가맨·프리솔로·소셜딜레마) = 호러서 멀고 저밀도 = 도달가능 발견.

## 배운 점 · 주의 / 한계
- **안전 MMR 효과는 다봉(잡식) 유저에서 큼**: 단일 장르 데모는 근처 봉우리가 1개라 효과가 약하게(1.0→1.25) 보임. 실제 잡식 유저는 봉우리가 많아 더 크게 작동.
- **미탐 λ0.5는 같은 봉우리 프랜차이즈 일부 잔존**(공포 미탐에 잭애스 ×3). λ0.3으로 더 줄일 수 있음(소프트값, 상수 한 줄).
- **"봉우리 수" 지표는 봉우리 내 프랜차이즈 중복은 못 잡음** — MMR이 그 중복을 줄이는 건 별개 이득(이 지표로 안 보일 뿐).
- λ **적응형**(유저 봉우리 수가 많으면 λ↓로 더 펼치기)은 향후 검토 항목. 지금은 트랙별 고정 λ로 충분.
