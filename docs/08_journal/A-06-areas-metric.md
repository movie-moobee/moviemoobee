# A-06 · 미탐색·안전 영역 감지 + 안전 척도 결정 (F-MAP-03)

- 날짜 / 일정ID / 담당: 2026-06-11 · 3.2 (F-MAP-03) · 개발자 A(김호준)
- 브랜치 / 커밋: `feat/MAP-03-areas` · (커밋 예정)
- 한 줄 요약: 미관람 영화의 **안전(좌표거리 근접)·미탐색(KDE 저밀도) 후보**를 산출하는 `detect_areas` 구현. 안전 근접 척도는 **코사인 vs 유클리드를 실측 비교**한 뒤 **UMAP 좌표 거리(유클리드)로 확정**. (지도 밝기는 관심사 분리로 3.3에서 별도 함수.)

- *(검증용·커밋 안 함, 삭제됨)* `compare_areas.py`, `compare_highdim.py` — 척도 비교 일회성 커맨드.

### 리뷰 반영 (피어 3회)
- 시청 좌표/ID **쿼리 2번 → 1번 통합**(`_watched`).
- 안전·미탐색 선정 `sorted` → **`heapq.nsmallest`**(O(N log k), 카탈로그 커질 때 대비).
- **반환에서 전량 density dict 제거** → `{user_coord, safe, unexplored}`만(관심사 분리·키타입/메모리 이슈 동시 해소). 지도 밝기는 3.3로.
- `MIN_WATCHED_FOR_KDE` → **`KDE_MIN_SAMPLES=3`(수학 하한)** + **`MAP_MIN_WATCHED=5`(제품 정책)** 로 의미 분리.
- `user.coord_x/y`가 **캐시(별점변경 시 signals 갱신)** 임을 주석 명시(여기서 재계산 안 함 = F-MAP-00 불변식 유지). "여기서 직접 계산" 제안은 캐싱 무력화라 반려.
- **KDE를 미관람 좌표만 평가**(`kde(coords[unwatched])`) — 어차피 미탐색은 미관람 중 고르므로 전체 평가는 낭비. 거리도 미관람 부분집합으로 대칭화. (값 동일, 연산만 감소)
- **반려/보류**: Redis 정적캐시·Faiss/KDTree·`int(ids)`는 우리 규모(2,000+편, ids는 ORM 순수 int)엔 과설계/불필요. DI(배열 주입)는 핵심 수학이 이미 순수(`kde_density`)라 소비처(4.x) 생길 때.

## 어떻게 / 왜
- **KDE**: 본 영화 좌표로 `gaussian_kde(bw=0.3)` 학습 → 전체 영화 밀도. 높음=탐색됨, 낮음=미탐색. 같은 밀도가 지도 밝기(F-MAP-01)로도 쓰임. 시청<3편이면 공분산 특이 → 밀도 None.
- **안전**: 사용자 좌표(3.1 캐시)에서 **유클리드 거리**가 가까운 미관람 영화 Top N.
- **척도 결정 과정(코사인 vs 유클리드)** — 핵심:
  - 명세 원안은 "코사인 Top N"이었으나, **UMAP 2D 좌표의 원점(0,0)은 임의값**이라 "원점 기준 각도(코사인)"가 취향을 못 나타낸다(좌표 계산이 '밀어내기'를 버린 것과 동일 논리).
  - PoC-B(`2_recommend.py`)가 이미 코사인·유클리드를 **둘 다** 구현해두고 "검증 후 결정"으로 남겨둠 → 그 의도대로 데모 유저로 실측.
  - **결과**: 두 척도 Top10 **겹침 0~2/10**(완전히 다른 추천). **2D 코사인은 어느 유저든 무관한 외화 잡음**, 유클리드는 취향 군집(예: demo_b → 탑건·F1·우주전쟁·파이트클럽)을 정확히 잡음.
  - **반증 검토(제민희 대리 의견)**: "고차원에서 재야 공정". 저장된 `coords_model.pkl`로 **896차원 TF-IDF 복원해 고차원 코사인**도 비교 → demo_a에선 고차원 코사인이 오히려 최상(히어로 군집). 즉 **코사인은 자기 홈그라운드(고차원)에선 유효**함을 인정.
  - **그러나** 우리 시스템은 사용자 좌표·지도·KDE가 **전부 2D**(제품 정체성=2D 취향지도, 와이어프레임 고정). 고차원 추천은 아키텍처 변경(입장 B)이라 채택 안 함. **잠금된 2D 안에서는 유클리드 압승** → 유클리드 확정.

## 기능 동작 (흐름)
```
detect_areas(user)
  ├ 본 영화 좌표 → gaussian_kde → 미관람 저밀도 Top N → 미탐색
  └ 사용자 좌표(캐시) → 미관람 유클리드 거리 → 가까운 Top N → 안전
지도 밝기(F-MAP-01)는 같은 kde_density 를 본 영화 대상으로 3.3에서 별도 산출.
```

## 검증
- 데모 3명에 `detect_areas` 실행: 안전=취향 군집 근방(거리 오름차순), 미탐색=호러/외화 등 저밀도. `ruff`·`manage.py check`·`makemigrations --check` 통과.
- 척도 비교표(코사인/유클리드/고차원코사인)는 위 "결정 과정" 참조 — 데이터로 유클리드 채택 근거 확보.

## 배운 점 · 주의
- **추천 척도는 '공간'이 정한다**: 임베딩 일반론(코사인)이 아니라 *우리가 추천하는 공간*(2D UMAP)에 맞춰야 함. 2D에선 원점 무의미 → 유클리드. 좌표 계산의 '밀어내기 배제'와 같은 뿌리.
- **UMAP 2D는 정보손실 있음**: demo_a처럼 고차원에서 뭉친 군집이 2D에서 흩어질 수 있음. 추천 품질 일부를 내주는 대신 '시각 지도'를 얻는 의도된 트레이드오프.
- **검증 코드의 공정성**: 두 척도를 '높을수록 안전'으로 부호 통일 후 동일 내림차순 정렬, 겹침은 등수 아닌 **풀 교집합(set &)**으로 측정해야 대조군이 성립.
- **고차원 추천(입장 B) 여지**: 향후 추천 품질을 더 끌어올리려면 `.pkl`로 고차원 코사인 추천이 가능(좌표는 시각화 전용). 단 사용자 고차원 프로파일·UI 재설계 필요.
- **KDE 대역폭: 고정 0.3 → `scott`(적응형) 확정**: bw=0.3은 *절대 대역폭*이 아니라 데이터 공분산에 곱하는 *고정 factor* 다(퍼짐엔 적응). 단 factor 0.3이 **Scott(2D면 n^(-1/6), n=15→≈0.63)보다 좁아** 꼬리가 언더플로(demo_c 밀도 e-14)했다. Scott는 σ·n^(-1/(d+4))로 본 영화 수·퍼짐 둘 다에 적응 → 값 정상화(e-14→e-05). **검증(미탐색 Top10 픽 겹침 0.3 vs scott)**: demo_c 10/10·demo_b 8/10·**demo_a 1/10**. 즉 시청이 모인 유저는 픽이 강건하나, **퍼진 유저(demo_a)는 0.3의 노이즈성(언더플로) 꼬리 탓에 픽이 사실상 무작위였다가 Scott로 더 안정화**됨. 안전(거리)은 대역폭과 무관하게 불변.
- **남은 후속**: `safe_top`/`unexplored_top` 노출은 4.1/4.2 API에서, KDE 밀도 정규화(0~1, 지도 밝기)는 3.3에서.

## ⚠️ 알려진 한계 / 후속 설계 (지도 담당 인지)
- **시청 5편 미만 게이트**: 온보딩(1.2)은 5편을 강제하지만 **가입 후 시청기록 삭제로 5편 밑으로 내려갈 수 있다.** → `detect_areas`에 **방어 가드 추가**: `len(watched) < MAP_MIN_WATCHED` 면 `{user_coord:None, safe:[], unexplored:[], enough:False}` 즉시 반환(무거운 `_all_movies` 전에 차단). `KDE_MIN_SAMPLES=3`은 별개의 KDE 수학 하한.
- **계획(합의)**: 삭제 자체는 막지 않고 **지도에서 경고**. 진짜 차단(호출 스킵)은 **진입부 공유 게이트**(3.3/4.x 엔드포인트의 permission/헬퍼)가 `watched_count < MAP_MIN_WATCHED` 확인 → 미만이면 detect_areas 호출 없이 *"영화를 N편 더 등록하세요"* 오버레이. detect_areas의 `enough:False`는 그 호출부가 잊어도 잘못 노출 안 되게 하는 belt-and-suspenders.
  - `MAP_MIN_WATCHED(5)`는 **온보딩(B)과 동일 값** → 추후 단일 출처 공유. 삭제 경고창(B 2.3)에 "5편 미만 시 지도 비표시" 안내 추가하면 UX 매끄러움. **→ B 공유 필요.**
- **카탈로그 규모**: 현재 299편이나 **목표 2,000+편**(추후 더 확대 가능). 2,000편은 메모리·`heapq` 모두 무난하나, 추세 대비 정렬·쿼리는 이미 효율형으로 둠. 수만 편 이상이면: ① 전역 고정 좌표라 `_all_movies` 결과를 인메모리/Redis 정적 캐시로 공유(요청마다 DB IO 제거), ② 안전 후보를 공간 인덱스(KDTree/Faiss/pgvector)로 KNN. (지금은 과설계라 보류.)
- **0편/저시청 blackout 폴백**: 좌표 None(0편)·`<MAP_MIN_WATCHED`면 `detect_areas`가 빈 배열 반환 → '추천 블랙아웃'. 폴백(인기 top N 등)은 `detect_areas`가 아니라 **추천 엔드포인트(4.x)·지도 게이트(3.3) 상위 레이어** 책임(서비스는 순수 유지). <5편 경고 게이트와 같은 자리.
- **미탐색 추천(4.2)은 "절대 최저밀도" ❌ → "저밀도 존 + 사용자좌표 거리 30–70 분위수" ✅(결정)**: 절대 최저밀도 Top-N은 (a) KDE 꼬리라 랭킹이 노이즈, (b) 의미상 *가장 이질적* 이라 "좋아하게 될" 가치와 어긋남. 시각화로 확인 — demo_a에서 절대최저=순수 공포 외딴섬, 30–70=공포·스릴러 하이브리드(demo_a 부취향 스릴러로 *도달 가능*). PoC `recommend_from_unexplored`와 동일 방식. 30–70은 잠정 기본값, 추후 튜닝. `detect_areas`(3.2)는 저밀도 후보까지만 책임, 이 선정은 4.2에서.
- **데이터 대중성 필터(별도 작업, chore/data)**: `/movie/popular`는 저득표(예: vote_count 4표) 옛날·외국 영화가 섞임 → `/discover/movie?sort_by=popularity.desc&vote_count.gte≈300&include_adult=false`로 교체 예정. 재수집 시 build_coords re-bake + fixture 갱신 필요(B 조율). 현재 카탈로그 <100표가 101/299편.
- **광역/다봉 취향 — 단일 무게중심 약점(검증됨)**: demo_a(액션 팬)의 안전추천이 코미디로 나왔다. 원인은 *sparsity 아님* — 액션은 **101/299편(전체 1/3)** 로 충분하고 중심 최근접 액션 0.74 ≈ 코미디 0.63. 진짜 원인은 좋아요 영화가 **중심에서 평균 5.84 떨어질 만큼 흩어져**(demo_c 3.73 대비) 무게중심이 텅 빈 한복판(코미디 군집)에 떨어진 것. 영화 수와 무관(그 10편이 고정). 단 "액션"이 1/3을 차지할 만큼 **장르 라벨이 거친 것**은 사실 → **2,000+편·더 세분화된 키워드면 하위 군집이 분리돼 개선될 여지** 있음(재검증 항목). 근본 개선은 다봉 취향의 군집별 표현(3.1/추천 설계, 별도 작업).
