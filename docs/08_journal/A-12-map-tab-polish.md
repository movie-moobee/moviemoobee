## 어떻게 / 왜

### ① 별 재클릭 → 선택 해제
`onSelect`가 무조건 선택만 했음 → 같은 `movie_id` 재클릭 시 `selectedId=null` + `emit("select", null)`.
부모(MapView)는 `@select="selected=$event"`라 null이면 선택 패널(`v-if`)·강조 링이 자동으로 사라짐. 부모 무수정.

### ② "내 취향 요약" (와이어프레임 10 우측 박스) — 핵심 의사결정
박스는 **장르명**으로 "주 클러스터 / 미탐색"을 보여준다. 좌표가 아니라 장르 기반.

- **주 클러스터 = 별점 가중**: 처음엔 단순 시청 빈도(count)로 갔으나, 작은 정수라 **동률이 흔하고**(데모에서 SF·액션 4편 동률), 동률을 DB가 임의로(컬레이션·id) 깨 **새로고침마다 뒤집힐 수** 있었다. → `weight = max(rating-3, 0)` 가중합으로 교체. 사용자 좌표(coords.py)·안전추천과 **동일 철학**(싫어한 장르는 취향 대표 아님)이라 시스템 일관성↑, 동률은 "더 좋아한 장르"가 이겨 자연 해소. 좋아요 0편이면 `Σw≈0` → count 폴백(coords.py와 같은 패턴).
- **미탐색 = KDE(좌표공간), 카탈로그 빈도 아님**: "안 본 큰 장르"(카탈로그 크기순)로 내면, 카탈로그가 인기수집이라 드라마·스릴러·범죄로 쏠려 **누구에게나 같은 장르**가 반복됨(9유저 중 범죄 6·스릴러 4 = 편향). → 실제 추천 엔진과 같은 `detect_areas`의 **KDE 미탐색 추천 영화의 장르를 역집계**. 좌표 기준이라 유저별로 갈림(공포→다큐·서부, 범죄→역사·전쟁). KDE 비용은 측정상 `detect_areas` ~6ms, `get_map` 전체 ~12ms로 무시 가능.
  - **드라마 누수**: 드라마가 최대 장르(2026편)라 KDE 미탐색 영화에도 자주 섞여(누수) 주 클러스터와 겹침. → **이미 본 장르 제외**로 해결(겹침 0, 드라마 누수 5→1).
  - **2칸 강제 보충**: KDE 후보 중 새 장르가 0·1개면(취향 넓은 유저) 칸이 빔 → "안 본 큰 장르"(카탈로그순)로 부족분만 채움. 1칸은 개인화, 보충분만 카탈로그.

### ③ 등록 탭 → 본 영화는 수정 모달
검색 결과는 `MovieListSerializer`(=`my_record` 없음)라 모달이 항상 생성 모드 → 본 영화 저장 시 중복 400("이미 등록한 영화"). 상세 페이지 패턴대로 `getMovie(id)`로 `my_record`를 받아 `initialRecord`로 넘김(있으면 수정). 모달은 setup에서 `initialRecord`를 1회만 읽으므로 **record 확정 후 마운트**.

## 배운 점 · 주의
- **동률은 결정적으로**: 작은 정수 순위는 동률이 흔하고 DB 정렬은 동률 순서를 보장 안 함 → 의미 있는 가중(별점) 또는 명시 tiebreaker 필수.
- **Django 다중 집계 함정**: `Sum`/`Count`를 한 쿼리에 섞으면 다중 조인이 행을 교차곱해 값이 부풀려짐 → 쿼리당 집계 1개로 분리.
- **라벨 ≠ 엔진의 위험**: 요약 라벨을 손쉬운 카탈로그 빈도로 내면 데이터 쏠림이 그대로 편향으로 노출 → 실제 추천 엔진(KDE)과 같은 신호를 써 일관 유지. (cf. 좌표공간 KDE = [[A-09]], 안전 kNN = [[A-08]])
- "미탐색"의 두 정의(이진 '안 본 장르' vs 좌표 '도달 가능 미탐색')를 구분 — 요약 박스는 헤드라인, 전체 미탐색 탐색은 4.4 지도 탐색 탭 담당.
